# Проверка проекта

Дата: 17 октября 2026 года.

Проверенное окружение: Python 3.12.14, python-telegram-bot 22.8,
yt-dlp 2026.8.19, yt-dlp-ejs 0.8.0, Node.js 24.19.0, FFmpeg и ffprobe.

**54 автоматических теста.** Они проверяют:

- настройки, скрытие токена из представления конфигурации, ограничения доступа;
- HTTP(S) ссылки, скрытые ссылки, подписи и смещения после emoji в Telegram;
- блокировку служебных IP, подмены адреса через DNS и реального локального
  socket-соединения в отдельном процессе;
- работу дочернего процесса и выдачу понятной ошибки без утечки исходного адреса;
- границы очереди, одну активную заявку на пользователя, последовательную обработку;
- отмену ожидающей и выполняемой заявки, удаление временных файлов;
- сохранение качества в SQLite между открытиями;
- обработку настоящего синтетического MP4 с видео и звуком;
- воспроизводимость всех частей, размеры и сохранение общей длительности;
- резервный способ деления видео с большим расстоянием между ключевыми кадрами;
- преобразование несовместимого видеокодека в H.264;
- полный путь через настоящий общий обработчик и загрузчик yt-dlp с имитацией
  ответа CDN, затем проверкой файла через настоящий ffprobe.

Также проверяются синтаксис Python, статический анализ Ruff, конфигурация Compose
и команда `python -m videobot --check` с тестовым токеном. `--check` не обращается
в Telegram и не подтверждает действительность токена.

Живая отправка в Telegram, вход по cookies, загрузка с каждой реальной площадки
и сборка Docker-образа в этой среде не выполнялись: настоящий токен и аккаунты
не предоставлены, Docker отсутствует. Эти проверки выполняются владельцем после
запуска. Имитация CDN не доказывает доступность конкретного сайта из сети сервера.
