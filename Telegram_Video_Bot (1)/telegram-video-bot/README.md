# Telegram Video Bot

Бот на Python: отправляете ссылку → бот скачивает видео → присылает MP4 в Telegram.
Большие ролики автоматически делятся на воспроизводимые части.

## Что поддерживается

Для извлечения видео используется **yt-dlp**. В нём есть обработчики TikTok, Pinterest,
YouTube (включая Shorts), Instagram, VK / VK Video, Rutube, Facebook, X/Twitter,
Vimeo, Dailymotion, Reddit, Twitch, OK и многих других сайтов. Короткие ссылки
вроде `youtu.be`, `vm.tiktok.com` и `pin.it` тоже обрабатываются, если площадка
даёт доступ из сети сервера.

Наличие обработчика не гарантирует загрузку каждого ролика. Сайты меняют защиту,
требуют авторизацию, ограничивают регион или IP. Универсального скачивания любых
видео со всех сайтов не существует. На неизвестных сайтах yt-dlp пробует общий
обработчик встроенного видео. Если он не нашёл видео, бот объяснит ошибку.

По умолчанию скачивается один ролик, а не канал, плейлист или подборка. Прямые
эфиры, DRM и снятие ограничений доступа не поддерживаются. Бот не обещает убрать
водяной знак: он получает файл, который доступен у источника.

## Самый простой запуск: Docker

1. Создайте бота у [@BotFather](https://t.me/BotFather): `/newbot`, имя и username.
   Сохраните выданный токен у себя.
2. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/)
   или Docker Engine с Compose на сервере.
3. Распакуйте архив. Скопируйте `.env.example` в `.env`. Вставьте токен:

   ```dotenv
   BOT_TOKEN=ваш_настоящий_токен
   ```

4. Откройте терминал в папке проекта и запустите:

   ```sh
   docker compose up -d --build
   ```

5. Откройте своего бота в Telegram, нажмите **Запустить**, отправьте ссылку на видео.

Проверить журнал: `docker compose logs -f --tail=50`.
Остановить: `docker compose down`.
Обновить yt-dlp и пересобрать: `docker compose build --pull --no-cache`, затем
`docker compose up -d`.

В образ уже включены Python, FFmpeg и Deno. Порты снаружи открывать не нужно:
бот получает сообщения через long polling. Нужен исходящий интернет к Telegram,
площадкам и их CDN. Контейнер работает от отдельного пользователя.

## Запуск на Windows без Docker

1. Установите [Python 3.12](https://www.python.org/downloads/) с пунктом **Add Python
   to PATH**, [FFmpeg](https://ffmpeg.org/download.html) (включая `ffprobe`) и
   [Node.js 22 или новее](https://nodejs.org/en/download) либо
   [Deno](https://docs.deno.com/runtime/getting_started/installation/).
   Для YouTube нужен JavaScript runtime. Бот сам обнаруживает Node.js или Deno.
2. После установки откройте новое окно терминала. Проверьте `ffmpeg -version`,
   `ffprobe -version` и `node --version` (либо `deno --version`). Если команды
   не найдены, добавьте папки с программами в PATH и перезапустите терминал.
3. Дважды нажмите `start.bat`. При первом запуске откроется `.env`. Вставьте токен,
   сохраните файл и запустите `start.bat` ещё раз.
4. Окно должно оставаться открытым, пока нужен бот.

Ручной вариант, если удобнее:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
.venv\Scripts\python.exe -m videobot --check
.venv\Scripts\python.exe -m videobot
```

Если зависимости не установились с первого раза, повторите команду установки
через `pip` выше. Токен уже работающего бота менять не нужно.

## Запуск на Linux без Docker

Нужен Python 3.12+ и FFmpeg. Для Debian/Ubuntu установите доступные в вашей версии
пакеты `python3`, `python3-venv`, `ffmpeg`; проверьте `python3 --version`.
Если системный Python старее 3.12, используйте Docker или установите Python 3.12+.
Установите Deno по его официальной инструкции либо Node.js 22+.

```sh
cp .env.example .env
nano .env
bash start.sh
```

Бот работает, пока запущен его процесс. Для постоянной работы используйте свой
сервер или постоянно включённый компьютер; Docker Compose перезапускает контейнер.
Хостинг и уже зарегистрированный Telegram-бот в архив не входят.

## Как пользоваться

| Команда | Действие |
|---|---|
| `/start` | Начало работы |
| `/quality` | Кнопки выбора качества |
| `/quality 1080` | Сохранить качество до 1080p |
| `/quality best` | Максимум, который отдаёт источник |
| `/cancel` | Отменить свою загрузку или ожидание |
| `/status` | Узнать состояние |
| `/id` | Получить свой Telegram ID |
| `/help` | Возможности и текущие лимиты |

Отправляйте **одну ссылку в одном сообщении**. Можно использовать кнопку
«Поделиться → Копировать ссылку» в приложении площадки. Поддерживается текст вокруг
ссылки и ссылки из подписи. У пользователя может быть одна текущая заявка.
Настройка качества сохраняется после перезапуска. Уже принятая заявка использует
качество, выбранное в момент её отправки.

## Размеры, качество и очередь

Облачный Telegram Bot API принимает отправляемые ботом файлы до **50 МБ**.
Поэтому здесь установлен запас: **49 000 000 байт на часть**. По умолчанию:

- загрузка с сайта до 500 МБ, длительность до 60 минут;
- до 30 отправляемых частей;
- 2 одновременные заявки и до 10 ожидающих;
- до 30 минут обработки одной активной заявки вместе с отправкой;
- 720p как верхняя граница качества, с вариантами 360/480/720/1080/best.

Это настраивается в `.env`. MB в параметрах означает **1 000 000 байт**.
Исходник больше 500 МБ отклоняется: выберите 480p/360p или увеличьте лимит владельцем.
Если сайт не сообщает размер заранее, загрузка прекращается при достижении лимита.

MP4 H.264/AAC небольшого размера отправляется без перекодирования. Другие
контейнеры преобразуются в MP4; несовместимые кодеки перекодируются в H.264/AAC.
Для деления обычно используется копирование потоков с границами по ключевым кадрам.
Из-за переменного битрейта части могут иметь разную длину. Слишком большой
отдельный фрагмент перекодируется. В этих случаях качество может немного снизиться.

При нехватке места, превышении времени, числа частей или сетевой ошибке бот
завершает заявку с сообщением. Полученные до отмены части остаются в чате.
Временные файлы и копии cookies удаляются после каждой заявки, включая отмену.
После аварийного отключения старые папки заявок удаляются при запуске через сутки.
Очередь находится в памяти: после перезапуска ожидающие ссылки нужно отправить заново.
Сообщения, накопившиеся за время отключения, при запуске пропускаются.

Ориентир для небольшого сервера: 2 ядра, 2 ГБ RAM и 8–10 ГБ свободного диска.
Перекодирование длинного видео требует CPU. На слабой машине поставьте
`MAX_CONCURRENT_DOWNLOADS=1`; лимит свободного диска проверяется перед запуском.
Не запускайте две копии одного бота одновременно.

## Cookies и вход в аккаунт

Иногда Instagram, Facebook, VK, YouTube и другие сайты требуют авторизацию
даже для просмотра публичного видео. Владелец может добавить **свои** cookies
в формате Netscape, если аккаунту разрешён доступ к ролику.

1. Подготовьте файл `cookies.txt` своего аккаунта в формате Netscape.
   Используйте только доверенный способ экспорта. Справка yt-dlp:
   [cookies FAQ](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#how-do-i-pass-cookies-to-yt-dlp).
2. Сохраните файл в `secrets/cookies.txt`.
3. Для Docker задайте `COOKIES_FILE=/app/secrets/cookies.txt`. При обычном запуске:
   `COOKIES_FILE=secrets/cookies.txt`.
4. В Linux при необходимости дайте чтение UID 10001 контейнера; не делайте файл
   общедоступным. Например, смените владельца файла на UID 10001 и права на 600.
5. Перезапустите бота. При истечении сессии замените файл cookies.

Cookies применяются **ко всем разрешённым пользователям** бота. Поэтому при их
использовании задайте `ALLOWED_USER_IDS` своими ID. Пустое значение открывает бота
всем. Бот не принимает токены, cookies и пароли через сообщения Telegram.
Не кладите `.env` и `secrets` в публичный репозиторий.

## Отправка одним файлом до 1950 МБ: необязательный режим

Для больших файлов без деления можно поднять собственный
[Telegram Bot API server](https://github.com/tdlib/telegram-bot-api) с флагом
`--local`. Его официальный лимит загрузки — 2000 МБ. Для него потребуются
`api_id` и `api_hash` с [my.telegram.org](https://my.telegram.org/), помимо токена бота.
Сам сервер не включён в Compose: это отдельный вариант развёртывания.

1. Поднимите сервер по официальной инструкции в доступной боту закрытой сети.
2. Укажите в `.env` `LOCAL_BOT_API_URL=http://адрес-сервера:8081`,
   `MAX_UPLOAD_MB=1950` и, например, `MAX_DOWNLOAD_MB=2000`.
3. Остановите прежний процесс бота. Один раз выполните
   `python -m videobot --logout-cloud` (через Python своего venv или
   `docker compose run --rm bot python -m videobot --logout-cloud`).
   Это вызывает официальный `logOut` для перехода с облачного сервера.
4. Запустите бота как обычно. Файлы передаются локальному API потоковым multipart,
   поэтому общая папка с ним не требуется.

При отдельном контейнере `127.0.0.1` означает сам контейнер бота. Используйте DNS-имя
сервиса в одной Docker-сети или корректный адрес хоста. Обычный запуск через облачный
API не даст отправить 2 ГБ простым изменением числа в `.env`: конфигурация это запрещает.

## Обновление и диагностика

Если перестала работать конкретная площадка, сначала обновите yt-dlp и его EJS:

```sh
python -m pip install -U "yt-dlp[default]"
```

Используйте Python своего venv; на Windows это `.venv\Scripts\python.exe`,
на Linux — `.venv/bin/python`. После обновления перезапустите бота.

- `--check` проверяет настройки и наличие FFmpeg, без запросов в Telegram.
- «Сайт требует вход» → обновите cookies владельцем.
- «Видео недоступно» → проверьте доступность из региона и сети сервера.
- «Requested format» / не найдено видео → попробуйте отдельный ролик или меньшее качество.
- YouTube требует JavaScript → проверьте версию Deno/Node и пакет `yt-dlp[default]`.
- `Conflict` → остановите вторую копию бота.
- Бот молчит в группе → для надёжной работы отправляйте ссылки в личный чат с ботом;
  режим приватности групп управляется отдельно у @BotFather.

Логи не печатают исходные ошибки сайтов, cookies, токен или полные URL запросов.
В SQLite хранятся только ID и выбранное качество; история ссылок не сохраняется.
Рабочие процессы не получают токен Telegram. Локальные/служебные IP, нестандартные
порты и схемы кроме HTTP(S) заблокированы; сетевые запросы FFmpeg отключены.
Для публичного сервиса дополнительно ограничьте исходящую сеть средствами хостинга:
проверки в Python не являются системной песочницей.

## Проверки для разработчика

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check .
```

Тесты не требуют токена: проверяют адреса, настройки, обработку ссылок, сохранение
качества, очередь/отмену, обработку MP4 и деление настоящего тестового видео FFmpeg.
Для тестов обработки видео нужны FFmpeg с `libx264` и ffprobe.
Состояние конкретных площадок и доставка через Telegram проверяются отдельно
владельцем после запуска с настоящим токеном.
